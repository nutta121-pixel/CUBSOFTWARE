Setup Guide

1

Create a Discord Application

Go to the Discord Developer Portal and click New Application. Give it a name — this becomes the presence title (e.g. "Playing YourApp").

2

Copy Your Application ID

On your application page, copy the Application ID (Client ID) and paste it into the Application ID field in CubPresence.

3

Add Images (Optional)

In the Developer Portal go to Rich Presence › Art Assets. Upload images and give them keys. Use those keys in the Large/Small Image fields, or use direct https:// URLs.

4

Configure & Connect

Fill in your Details, State, Timestamp, and Buttons. Click Connect to Discord. Make sure Discord is running first.

Pro Tips

  • Use placeholders like {time}, {day}, {day_num}, {month}, {timezone} in Details/State for live-updating text
  • Save profiles to quickly switch between different setups
  • Set up global hotkeys in Settings to connect/disconnect without opening the app
  • Use Presence Rotation to automatically cycle through multiple profiles
  • Enable "Always on top" to keep CubPresence visible while gaming
  • You cannot click your own buttons — ask a friend to test them

What's Fixed — v1.3.19

Linux — Discord Connection

  • Fix: "Discord not found" on Linux — RPC scanner now tries both 127.0.0.1 and ::1 (IPv6) in parallel for each port (6463–6472). On many Linux systems Discord binds to the IPv6 loopback address instead of IPv4, causing all connection attempts to silently fail.
  • Fix: Error message updated to advise Linux users to use the standard .deb or .tar.gz install instead of Snap/Flatpak if the issue persists.
  • Improvement: Per-port failure log entries now show as info (grey) instead of error (red) to reduce log noise during the port scan.

v1.3.14 — previous release (41 fixes)

Stability & Crashes

  • Fix: App crashed on quit if Discord was connected — sendToRenderer now checks isDestroyed() before writing to webContents
  • Fix: Connecting while already connected triggered an unintended auto-reconnect — old client destroy is now guarded with isManualDisconnect
  • Fix: Export profiles crashed on write failure — now caught and shown as an error dialog
  • Fix: Second-instance handler was registered inside whenReady() — moved before it so fast relaunches are handled correctly

Connection & Reconnect

  • Fix: Manual disconnect triggered auto-reconnect — isManualDisconnect flag added to block it
  • Fix: Rotation not stopped when user disconnected manually
  • Fix: Rotation timer callback was not async — setActivity() was fire-and-forget, so rotation errors were silently ignored
  • Fix: Disabling Auto-reconnect mid-countdown left the status bar stuck on "reconnecting in Xs…" — timer is now cancelled immediately
  • Fix: Activity update failure (e.g. Discord hiccup) incorrectly hid the Disconnect/Update buttons — uses a non-disconnecting error state now
  • Fix: "Presence updated!" shown even when the update failed
  • Fix: connect() catch block scheduled reconnect even during manual disconnect

Tray & Quick Connect

  • Fix: Tray Quick Connect silently failed on first-ever launch — renderer's savedClientId was stale; main now forwards it in the event payload
  • Fix: Tray Quick Connect showed "Please enter an Application ID" if the field was empty but a saved ID existed

Window

  • Fix: Window restored off-screen after disconnecting a secondary monitor — bounds are now validated against all active displays
  • Fix: Update install button called checkForUpdates instead of quitAndInstall

Profiles & History

  • Fix: Renaming a profile to an existing name silently overwrote it — now shows a warning
  • Fix: Duplicating a profile with an already-taken copy name silently overwrote it — now auto-increments (copy 2, copy 3…)
  • Fix: Party ID regenerated on every presence update, causing Discord to reset the party display — now stable per connection

UI & Presets

  • Fix: Streaming preset didn't show the Stream URL field
  • Fix: Clear preset and Clear Data left largeImageText / smallImageText character counters showing stale counts
  • Fix: streamUrl field not cleared by Clear Data
  • Fix: Rotation interval accepted negative values, causing Discord spam — minimum 5s enforced
  • Fix: Clear Data left activity type, stream URL field, timestamp radio, and custom timestamps panel in whatever state the user had them
  • Fix: Update error banner silently disappeared; error message now shown briefly in red
  • Fix: Stale countdown_end used after reconnect — now validated against current time, falls back to 1 hour
  • Fix: parseInt called without radix on countdown preset value — changed to parseInt(…, 10)

Main Process

  • Fix: setActivity() could receive null and throw — null guard added at function entry
  • Fix: Tray Disconnect click handler was not async — fire-and-forget disconnect could leave tray state out of sync
  • Fix: isManualDisconnect flag never reset if an exception was thrown inside disconnect() — wrapped in try/finally
  • Fix: connect() could be invoked concurrently (e.g. rapid hotkey presses) causing duplicate RPC clients — guarded with isConnecting flag
  • Fix: dialog.showSaveDialog / showOpenDialog called without checking if the window is destroyed — crashes avoided with isDestroyed() guard
  • Fix: mainWindow.setAlwaysOnTop() and setOpacity() in settings handler lacked isDestroyed() check — could throw on window close
  • Fix: set-always-on-top and set-opacity IPC handlers also lacked isDestroyed() check when called directly from renderer
  • Fix: show-message-box IPC handler passed mainWindow directly to dialog.showMessageBox — now falls back to null if window is destroyed
  • Fix: open-external IPC handler discarded the shell.openExternal() Promise — unhandled rejection on failure; now caught and swallowed

Renderer

  • Fix: populateFields() crashed with "Cannot read property of null" when called with a null activity — null guard added
  • Fix: 8 parseInt() calls were missing a radix argument — all updated to parseInt(…, 10) for strict decimal parsing

Presence Rotation

  • Fix: Rotation updated the preview but not Discord — rotation now requires an active connection before starting
  • Fix: First profile (index 0) was skipped — the timer incremented the index before the first setActivity call, so profile[0] was never sent to Discord; first profile is now applied immediately on start
  • Fix: No feedback when rotation failed to start due to not being connected — a warning dialog is now shown

Placeholders

  • Fix: Placeholders like {day}, {month}, {year} showed as literal text in Discord — resolution only happened in the renderer preview; main process now resolves them before sending to Discord RPC
